# Sailfish OS 5.2 на Samsung Galaxy M52 5G (m52xq) с mainline-ядром: сборка шаг за шагом

Родной Sailfish OS 5.2.0.22 без libhybris и Android: корень собирается из репозиториев Jolla, железо — слой `m52xq` mainline-портов.
Установка готового архива — [MANUAL-RU.md](MANUAL-RU.md), состав выпуска — [CHANGES-v1-RU.md](CHANGES-v1-RU.md), что дальше — [ПЛАНЫ.md](ПЛАНЫ.md).

Образец пути — [moWerk/sailfishos-pro1x-mainline](https://github.com/moWerk/sailfishos-pro1x-mainline) (F(x)tec Pro1-X).

> Образ содержит закрытые компоненты Jolla (Silica, Lipstick, приложения). Разрешения публиковать готовый образ не найдено: в репозитории
> только скрипты, патчи и слой без прошивок.

## 1. Что нужно на компьютере

Linux x86_64, sudo, около 30 ГБ, qemu-user-static с binfmt.

```sh
sudo apt install qemu-user-static binfmt-support p7zip-full gdisk e2fsprogs rsync zip curl git adb
B=~/m52-sailfish; mkdir -p $B/sdk && cd $B
git clone https://github.com/korryasdlerto-lgtm/samsung-m52xq-sailfishos repo
```

## 2. Сборочный chroot: SDK target

SDK target версии 5.2 нет, берётся последний 5.1.0.11; целевой корень ставится из 5.2.0.22.

```sh
cd $B/sdk
U=https://releases.sailfishos.org/sdk/targets/Sailfish_OS-5.1.0.11-Sailfish_SDK_Target-aarch64.tar.7z
curl -sSLO $U && curl -sSLO $U.md5sum && md5sum -c *.md5sum
sudo mkdir -p target
7z x -so *.tar.7z | sudo tar -x -C target --numeric-owner
sudo cp /usr/bin/qemu-aarch64-static target/usr/bin/; sudo cp /etc/resolv.conf target/etc/
sudo chroot target /bin/sh -c 'head -3 /etc/os-release; zypper --version'
```

## 3. Базовый корень 5.2.0.22 (stage1)

```sh
cd $B; sudo mkdir -p rootfs sdk/target/sfos rootfs/proc rootfs/dev
sudo mount --bind rootfs sdk/target/sfos; sudo mount -t proc proc rootfs/proc
sudo mount --bind /dev rootfs/dev; sudo mount -t proc proc sdk/target/proc
sudo cp repo/image/stage1-base.sh sdk/target/root/
sudo chroot sdk/target /bin/sh /root/stage1-base.sh > stage1.log 2>&1; echo $?
sudo chroot sdk/target rpm --root /sfos -qa | wc -l            # 661
```

| Проблема | Причина | Решение |
|---|---|---|
| `ref` останавливается на native-common | репозиторий OBS не подписан (ни repomd, ни rpm) | подключается с `-G`; другого источника Mesa и alsa-ucm-conf для Sailfish нет |
| «public key is not available» посреди установки | пакет `ssu` переписал репозитории на `plugin:ssu`, ключа rpm 5.2 в SDK 5.1 нет | запустить stage1 ещё раз: его начало возвращает обычные подписанные репозитории |
| скриптлеты первых пакетов падают без `/bin/sh` | busybox ставится 114-м | переустановка этих пакетов в stage2 |

## 4. Донастройка корня (stage2)

```sh
sudo cp repo/image/stage2a-system.sh repo/image/stage2-reinstall.list sdk/target/root/
sudo chroot sdk/target sh /root/stage2a-system.sh > stage2a.log 2>&1; grep -c 'scriptlet failed' stage2a.log      # 0
```

Модули ядра и прошивки (Sailfish не usrmerge: `/lib/modules`, `/lib/firmware`) — из любого mainline-порта с тем же ядром 7.1.13
([kernel/](../kernel/README.md)), закрытые прошивки — только для своего телефона:

```sh
sudo cp -r --no-preserve=ownership,mode <корень>/usr/lib/modules/7.1.13 rootfs/lib/modules/
sudo cp -r --no-preserve=ownership <корень>/usr/lib/firmware/. rootfs/lib/firmware/
sudo chroot sdk/target chroot /sfos /sbin/depmod -a 7.1.13       # сообщение про modules.builtin.modinfo безвредно
```

Слой и доступ для первого запуска:

```sh
sudo cp -r repo/rootfs-overlay sdk/target/root/sparse; sudo cp repo/image/stage2c-access.sh sdk/target/root/
sudo chroot sdk/target sh /root/stage2c-access.sh
```

`usb-moded` отключается: он перенастроил бы USB-сеть, созданную initramfs. Двоичные файлы слоя — [EXCLUDED-FILES.txt](../EXCLUDED-FILES.txt).

## 5. Графика и масштаб

Lipstick запускается через eglfs_kms, файлы `var/lib/environment/compositor/` слоя:

- `60-m52xq.conf`: `QT_QPA_PLATFORM=eglfs`, `QT_QPA_EGLFS_INTEGRATION=eglfs_kms`, **`EGL_PLATFORM=drm`** (штатное `wayland` роняет lipstick, `gbm` Mesa 25 не
  знает), раскладка кнопок `QT_QPA_EVDEV_KEYBOARD_PARAMETERS=keymap=/usr/share/qt5/keymaps/droid.qmap`;
- `m52xq-kms.json`: `/dev/dri/card1`, выход `DSI-1`, 1080×2400.

Масштаб 1.75: `etc/dconf/db/vendor.d/m52xq-silica.txt` и пакеты графики z1.75, затем `dconf update`.

## 6. Пересборка программ

В отдельном chroot (копия корня 5.2.0.22) ставятся компилятор и заголовки:

```sh
sudo cp -a rootfs buildroot; sudo mkdir -p sdk/target/build; sudo mount --bind buildroot sdk/target/build
sudo cp repo/image/buildroot-repos.sh sdk/target/root/; sudo chroot sdk/target sh /root/buildroot-repos.sh
sudo chroot buildroot sh /root/build-sensors-1.sh      # protobuf-c 1.5.2, libssc 0.4.4 с патчами stk3a0x
sudo chroot buildroot sh /root/build-sensors-2.sh      # плагины sensorfw SSC
sudo chroot buildroot sh /root/build-ofono.sh          # ell 0.70, ofono 2.12 + QRTR
sudo chroot buildroot sh /root/build-ofono-0023.sh     # вторая SIM (остальные патчи 0024–0029 уже в series: данные на двух SIM)
sudo chroot buildroot sh /root/build-gps.sh            # geoclue с QMI LOC
sudo chroot buildroot sh /root/build-libcamera.sh      # libcamera 0.8.0 с патчами
sudo chroot buildroot sh /root/build-qtmultimedia.sh   # QtMultimedia v4l + qtmultimedia-v4l-m52xq.patch
sudo chroot buildroot sh /root/build-rawphoto.sh       # m52xq-rawphoto: фото 64 Мп
```

`m52xq-flashlight` и `m52xq-bt-awake` собираются одной командой каждая, см. `build/README.md`.

Модуль IPA в libcamera подписывается ключом сборки: ставьте `libcamera.so` и `ipa_softisp.so` (вместе с `.sign`) только из одной сборки.

Исходники и патчи — [build/](../build/README.md).

## 7. Что нужно знать по подсистемам

| Подсистема | Особенность |
|---|---|
| ADSP, модем | qrtr-ns, rmtfs, tqftpserv взяты из Debian (GLIBC ≤ 2.38); rmtfs стартует после `m52xq-adsp-start` |
| Датчики | правила udev — в `/lib/udev`, не `/usr/lib/udev`; `hexagonrpcd` запускать без обёртки (busybox `sh` её не понимает); тип датчиков для Qt — `etc/xdg/QtProject/Sensors.conf`; пользователь `fastrpc` создаётся отдельно |
| Wi-Fi | ath11k даёт случайный MAC на каждой загрузке, connman не узнаёт сеть; `m52xq-wifi-mac` ставит адрес из EFS |
| Bluetooth | адрес ставит `btmgmt public-addr` (первая попытка может дать «Invalid Index», скрипт повторяет) |
| Звук | UCM SM-M526B; PulseAudio без `name=` у `module-alsa-card`, иначе «Failed to create sink object»; политика ohm — плагины resolver, telephony, media, accessories, profile, dspep |
| Звонки | ofono ждёт `rmnet_data0-2` (создаёт `m52xq-modem-prep`); юнит без `--nobacktrace` |
| Две SIM | второй модем `/qrtrsoc_1`, `ModemCount=2` в `hw-settings.ini` |
| Экран у уха | `m52xq-incall-proximity`; датчик в mce выключен |
| GPS | серверы XTRA — `etc/gps_xtra.ini`, нужна включённая онлайн-помощь |
| Кнопки | без `droid.qmap` громкость не работает |
| Видео | в браузере декодируется программно |
| Браузер | его главный поток сам вызывает `swapBuffers` на каждый кадр (`DeclarativeWebContainer::renderCompositedFrame`); с Mesa вызов ждёт кадровый ответ оболочки, и касания с запросом «ты жив?» не разбираются («не отвечает»). Исправление в профиле песочницы: `env vblank_mode=0` (`build/browser/sailjail-browser.sh`) |
| Кэш шейдеров | каталог `~/.cache/mesa_shader_cache_db` в песочнице браузера лежал в оперативной памяти и терялся; профиль пробрасывает его на диск |
| Звук после загрузки | `m52xq-audio-reprobe` ищет контроллер выводов LPASS по адресу (`33c0000.*pinctrl`): имя зависит от дерева устройств |
| Мобильные данные | ofono 0024–0029: LTE уже подключён модемом, путь данных IPA MAPv5, у SIM 2 свои mux-каналы; SIM для данных ведёт `m52xq-dds-sync` |
| Сон | MCE усыпляет через `/sys/power/autosleep` и `wake_lock`, нужны `CONFIG_PM_AUTOSLEEP` и `CONFIG_PM_WAKELOCKS`; `m52xq-wow`: WoWLAN, `wow_flags=32`, `hw_filter=3`, `s2idle` (в `deep` при включённом Bluetooth все засыпания срываются) |
| Bluetooth во сне | линия UART (IRQ 158) будит телефон сразу: `m52xq-bt-awake` выключает Bluetooth при погашенном экране, если ничего не подключено; с гарнитурой держит телефон бодрствующим |
| Камера | libcamera: порядок камер задаёт `QT_GSTREAMER_CAMERA_FIRST`; в libcamera 0.8 Location называется `Front`/`Back`; песочнице нужны `/usr/share/libcamera`, `/dev/dma_heap`, `udmabuf` (udev и `firejail/disable-common.local`); фото 64 и 32 Мп делает `m52xq-rawphoto` |
| Экспозиция | AgcMSV качалась: одна поправка за раз с ожиданием; при старте потока не отправляется значение по умолчанию (патчи 0018, 0019) |
| Вспышка, фонарик | `/sys` в песочнице только для чтения: светодиод включает служба D-Bus `org.sailfish.flashlight.provider` (`m52xq-flashlight`) |
| Настройки камеры | песочница копирует `/etc` один раз при загрузке: правки dconf видны камере после перезагрузки |
| `/home` | на userdata (ext4), `m52xq-home-on-userdata`, без зависимостей от `sysinit.target` |
| Перед повтором `systemd-tmpfiles-setup` | стирает `/run/systemd/boot-status`: пустая правка `tmpfiles.d/sailfishos-cgroups.conf` |

## 8. Проверка без прошивки

```sh
sudo umount sdk/target/sfos/dev sdk/target/sfos/proc sdk/target/proc sdk/target/sfos 2>/dev/null
I=sailfish-test.img; truncate -s 2560M $I; mkfs.ext4 -q -F -L pmOS_root -O ^metadata_csum_seed $I; mkdir -p mnt; sudo mount -o loop $I mnt
sudo rsync -aHAX --numeric-ids --exclude='/proc/*' --exclude='/sys/*' --exclude='/dev/*' --exclude='/run/*' --exclude='/tmp/*' \
  --exclude=/usr/bin/qemu-aarch64-static rootfs/ mnt/
sudo umount mnt; e2fsck -fn $I
adb push $I /data/rootfs.img          # в TWRP; initramfs загрузит этот файл вместо раздела system
```

Откат: переименовать `/data/rootfs.img` в TWRP. Вход: `ssh root@172.16.42.1`, пароль `m52xq`.

## 9. Образ выпуска

Есть два пути.

**Слой на чистый корень** (так собран текущий выпуск): `image/release/assemble.sh <смонтированный корень p2>` ставит файлы слоя по одному,
ofono, камеру, службы, правит профиль песочницы браузера и `CaptureView.qml` камеры (md5 `cd60f9b6…` → `4ebe7247…`), ставит три RPM (libyaml, elfutils), выполняет `dconf update`.

**Снимок настроенного телефона и чистка** ([image/release/](../image/release)). Чистку запускать обязательно: снимок содержит личное
(данные, ключи, модем, данные блокировки экрана `usr/share/lipstick/devicelock`). Команды:

```sh
mkdir -p release/mnt-boot release/mnt-root && cd release
truncate -s 4G sailfish.img; L=$(sudo losetup -f --show -P --sector-size 4096 sailfish.img)
sudo sgdisk -o -n1:2048:133119 -c1:pmOS_boot -n2:133120:0 -t2:B921B045-1DF0-41C3-AF44-4C6F280D3FAE -c2:pmOS_root $L; sudo partprobe $L
sudo mkfs.ext2 -q -F -L pmOS_boot -U 701cd927-9574-4e7d-b83a-28138cb07da4 ${L}p1
sudo mkfs.ext4 -q -F -L pmOS_root -O ^metadata_csum_seed ${L}p2
sudo mount ${L}p1 mnt-boot; sudo mount ${L}p2 mnt-root
PHONE=172.16.42.1 sh ../repo/image/release/snapshot.sh
sudo R=mnt-root BASE=../rootfs OVERLAY=../repo/rootfs-overlay sh ../repo/image/release/cleanup.sh
```

Перед сжатием (после любого пути) — затереть свободное место и искать личные значения (IMEI, IMSI, ICCID, MAC, серийный номер, имена сетей) в файлах образа: совпадений быть не
должно. Затем `umount`, `e2fsck -fy`, `resize2fs -M`, уменьшить раздел 2 (`sgdisk -d2 -n2:…`), `sgdisk -e`, `sgdisk -v`.

Архив:

```sh
split -b 2684354560 -d -a 1 sailfish.img zip/data/rootfs-chunks/sailfishos-m52xq.img.part-
cd zip && zip -9 -r ../sailfishos-5.2-m52xq-mainline-v1.zip META-INF firmware data && unzip -tq ../sailfishos-5.2-m52xq-mainline-v1.zip
```

Файл внутри архива не больше 4 ГБ: `unzip` в TWRP тогда молча отдаёт пустоту, ближе к 5,4 ГБ не хватает памяти; сам архив может быть больше 4 ГБ.
В образе оставьте около 200 МБ свободного места (его расходует установщик).

`META-INF` — [installer/](../installer), `firmware/` — boot, vendor_boot, dtbo-frag ([kernel/](../kernel/README.md)).

## 10. Проверка после установки

```sh
ssh root@172.16.42.1                                    # по USB, пароль m52xq
cat /sys/power/mem_sleep                                # [s2idle] deep
cat /sys/module/ath11k/parameters/m52xq_wow_flags       # 32
systemctl is-active m52xq-wow m52xq-bt-awake m52xq-dds-sync ofono
echo 1 > /sys/power/pm_debug_messages                   # потом: journalctl -k -b | grep "Triggering wakeup"
```
